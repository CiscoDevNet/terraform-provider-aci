# Generated output ownership

The generator is intended to produce the complete generated output set in a
single run. It must remove stale generated files before writing the current
set, while preserving handwritten source files.

## Cleanup contract

The active generator must use one of these equivalent mechanisms:

- an explicit list of generated output roots and filename patterns; or
- a manifest containing the files produced by the previous run.

The preferred implementation is a manifest combined with declared output
roots. This allows stale files to be removed when a class or artifact is no
longer generated, without deleting handwritten files in the same directory.

Generation should render into a staging area first, validate the complete
file set, and then reconcile the staging area with the owned output paths. A
failed generation must not leave a partially regenerated repository.

## Template ownership

The former templates are stored in `gen/templates/legacy_templates/` for comparison and
migration reference. The active templates will be stored in `gen/templates/`.
Each active template must declare or be registered with the output artifact
it owns, so the generator can account for every expected file.
